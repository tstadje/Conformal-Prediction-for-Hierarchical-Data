# Python Simulation for Hierarchical Time Series Forecasting with Conformal Prediction

## Overview/Purpose
This project provides a Python-based simulation framework designed to analyze forecasting strategies for hierarchical time series. It focuses on generating synthetic hierarchical data, applying various forecasting models, implementing several forecast reconciliation techniques (Ordinary Least Squares - OLS, Weighted Least Squares - WLS, Minimum Trace - MinT, and a combination method "Combi"), and rigorously evaluating the resulting prediction intervals using conformal prediction methods. The primary aim is to assess the empirical coverage and interval length (or volume for joint regions) of these different approaches across diverse hierarchical structures and data generation processes, thereby offering insights into reliable uncertainty quantification in hierarchical forecasting.

## Project Structure
The project is organized into the following main directories and files:

-   `R/`: Contains the original R scripts that served as the basis for this Python translation. This includes scripts for core functions, simulation studies, result aggregation, table generation, and plotting.
-   `py_simulation/`: The root directory for the Python simulation package.
    -   `src/`: Contains all Python source code for the simulation and analysis pipeline.
        -   `functions.py`: This is the core module of the project. It houses the Python translations of R functions, including logic for:
            -   Hierarchical structure generation (`generate_S`).
            -   Synthetic hierarchical time series data generation (`generate_multi`).
            -   Base forecasting model fitting using Linear Models (LM) and Generalized Additive Models (GAM) (`prediction_fast`).
            -   Forecast reconciliation techniques (OLS, WLS, MinT, Combi) integrated within the main simulation loop (`simulation_multi`).
            -   Marginal and joint conformal prediction algorithms (`conformal`, `joint_conformal`).
            -   The main simulation orchestration logic (`simulation_multi`).
            -   Utility functions for LaTeX table generation (`get_table`, `get_table_occurence`).
        -   `study.py`: A command-line script to execute a single simulation instance for a specific configuration. It saves raw prediction interval metrics to a configuration-specific directory.
        -   `run_study_series.py`: A utility script to run `study.py` multiple times for a range of simulation indices for a single configuration.
        -   `gather.py`: A command-line script to aggregate results from multiple simulation runs (performed by `study.py`) for a given configuration.
        -   `latex_tables.py`: A script to process the aggregated results and generate LaTeX-formatted summary tables for key performance metrics.
        -   `plotting.py`: A command-line script to generate plots (e.g., Coverage vs. Interval Length) from the aggregated results for visual analysis.
        -   `main_pipeline.py`: The main orchestrator script to run the entire end-to-end workflow for a set of predefined configurations.
    -   `tests/`: Contains Python test files for `pytest`.
        -   `test_functions_*.py`: Unit tests for functions in `functions.py`.
        -   `test_pipeline_*.py`: Integration tests for the command-line scripts (`study.py`, `gather.py`, etc.) and the main pipeline.
    -   `requirements.txt`: Lists all Python package dependencies necessary to run the project, including test dependencies.
-   `Config_X/`: These directories (e.g., `Config_1`, `Config_2`) are created dynamically in the project root by `study.py` (when called by `run_study_series.py` or `main_pipeline.py`). They store:
    -   `simulation_{index}.pkl`: Pickled Pandas DataFrame containing marginal conformal prediction metrics for each series and method from a single simulation run (indexed by `simulation_index`).
    -   `simulation_joint_{index}.pkl`: Pickled Pandas DataFrame containing joint conformal prediction metrics for each method from a single simulation run.
    -   `Final_Output.pkl`: Aggregated marginal metrics from all simulation runs within that configuration, generated by `gather.py`.
    -   `Final_Output_joint.pkl`: Aggregated joint metrics from all simulation runs within that configuration, generated by `gather.py`.
-   `Plot/`: This directory is created in the project root by `plotting.py` (when called by `main_pipeline.py`).
    -   `Config_X/`: Subdirectories within `Plot/`, storing:
        -   `Config_{X}_CovLength_{SeriesName}.pdf`: PDF plots visualizing Coverage vs. sqrt(Interval Length) for each individual time series (`SeriesName` like V1, V2, etc.) within configuration `X`.
-   `LaTeX_file.txt`: Output file generated by `latex_tables.py` in the project root, containing LaTeX code for tables summarizing marginal prediction interval metrics.
-   `LaTeX_joint_file.txt`: Output file generated by `latex_tables.py` in the project root, containing LaTeX code for tables summarizing joint prediction region metrics.
-   `pytest.ini`: Configuration file for `pytest`, specifying test paths, coverage options, etc.
-   `README.md`: This file.

## Dependencies
The required Python libraries are listed in `py_simulation/requirements.txt`.
To install them, navigate to the project root directory in your terminal and run:
```bash
pip install -r py_simulation/requirements.txt
```
Key libraries include pandas, numpy, scipy (for statistics and linear algebra), statsmodels (for OLS), pygam (for GAMs), matplotlib (for plotting), and pytest (for testing).

## How to Run the Simulation
The simulation pipeline involves sequential execution of the Python scripts located in `py_simulation/src/`. **It is crucial to run these scripts from the project's root directory** so that relative paths for creating/accessing `Config_X` and `Plot` directories work as intended.

The original R project used shell scripts like `launcher.sh`, `run.sh`, and `eval.sh`, likely designed for SLURM/HPC environments to manage parallel execution of simulation configurations and individual runs. This Python project provides `py_simulation/src/main_pipeline.py` as a primary way to run the entire workflow locally for a set of predefined configurations, and `py_simulation/src/run_study_series.py` to manage batches of simulations for a single configuration. For large-scale experiments similar to the original R setup, these Python scripts would typically be called by a higher-level job management script (e.g., a new shell script using a job queue or parallel execution tools).

### Option 1: Running the Full Pipeline (main_pipeline.py) - Recommended for most users
The `py_simulation/src/main_pipeline.py` script is the primary way to run the entire end-to-end workflow. It automates running simulations for a predefined set of experimental configurations, gathering results, generating plots, and creating LaTeX summary tables.

**Key Arguments for `main_pipeline.py`:**
-   `--model-type {gam,lm}`: (Optional, default: `gam`) Specifies the forecasting model type to be used for all simulations run by the pipeline.
-   `--configs CONFIG_NUM [CONFIG_NUM ...]`: (Optional) A list of configuration numbers (e.g., `1 2 3`) to run. If omitted, all configurations defined within `main_pipeline.py` are executed.
-   `--skip-simulations`: (Optional flag) If provided, the pipeline will skip running new simulations (i.e., calls to `run_study_series.py`) and will proceed directly to the evaluation phase (gathering, plotting, table generation) using existing data in `Config_X` directories.
-   `--skip-evaluation`: (Optional flag) If provided, the pipeline will only run the simulation phase and will skip all evaluation steps (gathering, plotting, table generation).

**Example Command (run from project root):**
To run the full pipeline for configurations 1 and 3 using GAM models:
```bash
python py_simulation/src/main_pipeline.py --model-type gam --configs 1 3
```
To run only the evaluation phase for all predefined configurations:
```bash
python py_simulation/src/main_pipeline.py --skip-simulations
```

**Note on Configurations in `main_pipeline.py`:**
The script contains a hardcoded list of experimental configurations (e.g., different `l`, `n_bottom`, `n_obs` values). Users can modify this list directly in `main_pipeline.py` to define their desired experimental setups. For initial testing, the script is typically configured with a small number of simulations and observations.

### Option 2: Running Pipeline Components Manually
For more granular control or debugging, you can run the individual scripts. This is also useful for understanding the pipeline components that `main_pipeline.py` automates.

#### Step A: Running a Series of Simulations for One Configuration (run_study_series.py)
This script calls `study.py` multiple times to cover a range of simulation indices for a single configuration.

**Key Arguments for `run_study_series.py`:**
-   `--config_l`, `--config_n_bottom`, `--config_n_obs`, `--num_config`: Define the specific experimental configuration.
-   `--model_type`: 'gam' or 'lm'.
-   `--start_index`, `--end_index`: Define the range of simulation indices to run (e.g., 0 to 50 for 50 simulations).
-   (Other arguments like `--noise_type`, `--alpha` can also be passed).

**Example Command (run from project root):**
To run simulations 0 through 49 for configuration 1 (l=1, n_bottom=12, n_obs=200) using GAM:
```bash
python py_simulation/src/run_study_series.py --config_l 1 --config_n_bottom 12 --config_n_obs 200 --num_config 1 --model_type gam --start_index 0 --end_index 50
```
This internally calls `study.py` 50 times. Key arguments for `study.py` (like `--simulation_index`, `--num_simulations`) are managed by `run_study_series.py`.

#### Step B: Gathering Results for One Configuration (gather.py)
After `run_study_series.py` (or multiple `study.py` calls) complete for a configuration, `gather.py` aggregates their outputs.

**Key Arguments for `gather.py`:**
-   `--num_config`: The configuration ID.
-   `--num_simulations`: The total number of simulation files generated for that configuration.

**Example Command (run from project root):**
To gather results for configuration 1, where 50 simulations were run:
```bash
python py_simulation/src/gather.py --num_config 1 --num_simulations 50
```

#### Step C: Generating Plots for One Configuration (plotting.py)
`plotting.py` generates plots from the aggregated results of a single configuration.

**Key Arguments for `plotting.py`:**
-   `--num_config`: The configuration ID.
-   `--m_total_series`: The total number of series for this configuration (calculated as `1 + sum(12**i for i in range(1, l+1)) + n_bottom`).

**Example Command (run from project root):**
For configuration 1 (l=1, n_bottom=12 => m_total_series=25):
```bash
python py_simulation/src/plotting.py --num_config 1 --m_total_series 25
```

#### Step D: Generating LaTeX Summary Tables (latex_tables.py)
This script runs after results for *all relevant configurations* have been gathered. It reads from multiple `Config_X` directories.

**Example Command (run from project root):**
```bash
python py_simulation/src/latex_tables.py
```

## Testing
This project uses `pytest` for automated testing.

### Installation
Test dependencies, including `pytest` and `pytest-cov` (for coverage reports), are listed in `py_simulation/requirements.txt`. To install all necessary packages, navigate to the project root directory and run:
```bash
pip install -r py_simulation/requirements.txt
```

### Running Tests
To run all tests, navigate to the project root directory in your terminal and execute:
```bash
pytest
```
This command will automatically discover and run all tests located in the `py_simulation/tests/` directory, following the conventions defined in `pytest.ini`. Test results, including a summary of passed and failed tests, will be printed to the console.

A code coverage report will also be generated, indicating which parts of the source code in `py_simulation/src/` were exercised by the tests. This report is available in HTML format (in an `htmlcov/` directory created in the project root) and is also printed as a summary to the terminal, as configured in `pytest.ini`.

### Test Structure
The tests are organized as follows:
-   **Unit Tests**: Located in `py_simulation/tests/`, these files focus on testing individual functions within `py_simulation/src/functions.py`. They are categorized by the functionality of the functions they test:
    -   `test_functions_data_gen.py`: Tests for data generation functions like `generate_S` and `generate_multi`.
    -   `test_functions_conformal_recon.py`: Tests for conformal prediction logic (`_get_conformal_quantile`, `conformal`, `joint_conformal`), reconciliation helpers (`_calculate_G_matrix`, `root_det`), and LaTeX table utilities (`get_table`, `get_table_occurence`).
    -   `test_functions_forecasting.py`: Tests for the forecasting function `prediction_fast`.
-   **Integration Tests**: Also in `py_simulation/tests/`, these files test the interaction of multiple components, primarily the command-line pipeline scripts:
    -   `test_pipeline_simulation.py`: Tests the execution of `study.py` and `run_study_series.py`, ensuring they produce the expected file outputs.
    -   `test_pipeline_evaluation.py`: Tests `gather.py`, `plotting.py`, and `latex_tables.py`, verifying they can process simulation outputs and generate their respective artifacts.
    -   `test_main_pipeline.py`: Tests the main orchestrator script `main_pipeline.py`, including its command-line argument handling and ability to run the full workflow.

## Output Description
The primary outputs of the simulation pipeline are:

-   **`Config_X/Final_Output.pkl`**: A Pandas DataFrame containing aggregated marginal prediction interval metrics from all simulations for configuration `X`. Key columns include `method`, `Series` (e.g., 'V1', 'V2', ... representing different time series in the hierarchy), `metric` (e.g., 'Coverage', 'Length'), `Value` (the specific value of the metric from one simulation run), and `simulation` (the simulation run index).
-   **`Config_X/Final_Output_joint.pkl`**: A Pandas DataFrame containing aggregated joint prediction region metrics from all simulations for configuration `X`. Key columns include `method`, `metric` (e.g., 'Coverage', 'Volume'), `V` (the specific value of the metric from one simulation run, typically there's one set of joint metrics per simulation per method), and `simulation`.
-   **`Plot/Config_X/*.pdf`**: A set of PDF files, one for each time series in the hierarchy for configuration `X`. These plots visualize empirical coverage against the square root of the average interval length, with error bars, for different forecasting and reconciliation methods.
-   **`LaTeX_file.txt`**: Contains LaTeX code for tables that summarize marginal performance metrics (e.g., mean coverage ± SE, mean sqrt(length) ± SE) across different configurations and methods.
-   **`LaTeX_joint_file.txt`**: Contains LaTeX code for tables that summarize joint performance metrics (e.g., mean joint coverage ± SE, mean volume ± SE) across different configurations and methods.

## Core Functions (`py_simulation/src/functions.py`)
The `py_simulation/src/functions.py` file is central to this project, containing the Python implementations of the core scientific logic. Key functions include:

-   `generate_S`: Constructs the summing matrix `S` that defines the hierarchical aggregation structure based on the number of bottom-level series (`n`) and aggregation levels (`l`).
-   `generate_multi`: Generates synthetic time series data for all series in the hierarchy, incorporating specified exogenous features (X1, X2, X3) and noise characteristics.
-   `prediction_fast`: Fits base forecasting models (Linear Models or Generalized Additive Models) to the time series data using the exogenous features.
-   `simulation_multi`: The main orchestrator for a single simulation run. It handles data generation, splitting data into training, validation, calibration, and test sets, base forecasting, application of forecast reconciliation methods (OLS, WLS, MinT, Combi), and the use of conformal prediction techniques to evaluate prediction intervals.
-   `conformal`: Computes marginal (series-by-series) conformal prediction intervals and their empirical coverage and length.
-   `joint_conformal`: Computes joint conformal prediction regions for all series simultaneously and evaluates their empirical coverage and a volume proxy.
-   `metrics_proba_multi`: A utility function called by `simulation_multi` to manage the computation and collection of performance metrics from `conformal` and `joint_conformal` across different forecasting/reconciliation methods.
-   `get_table`, `get_table_occurence`: Helper functions to format Pandas DataFrames into LaTeX table strings for reporting results.

This file encapsulates most of the algorithms and procedures translated from the original R codebase, forming the scientific backbone of the simulation study.
